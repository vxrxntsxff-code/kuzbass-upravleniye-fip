## 📌 Структура платформы (по ТЗ)

1. **Главная** — приветствие «Управленческий навигатор Кузбасса», модель опережающей подготовки «на одной картинке» (диагностика → ИПР → подготовка → портфолио → повторная диагностика), фотогалерея ИРО, миссия, 5 возможностей участника, контакты.
2. **О проекте** — цель → задачи → миссия (схема), жизненный цикл руководителя в правильном порядке (отбор → диагностика → подготовка → назначение → аттестация → сопровождение), уникальность, ожидаемые результаты к 2030 году, команда.
3. **Ключевые направления** — 5 направлений управленческой деятельности с описаниями (без модулей и уровней сформированности).
4. **Пройти диагностику** — 4 блока о системе оценки, описание инструментов (прохождение — в личном кабинете), шкала уровней дефицитов.
5. **Образовательная траектория** — 4 формата обучения (ДПП ПК, онлайн-микромодули, форумы и интенсивы, межмуниципальные сетевые лаборатории — сеть из 31 опорной площадки), как строится ИПР.
6. **Эффективный диалог (вопрос-ответ)** — форма вопроса, лента консультаций; отвечают эксперты (роль `expert`).
7. **Кадровый резерв · Кузбасс.Будущее.РФ** — описание системы резерва, трёхуровневая модель, банк проектных инициатив с открытым голосованием, ссылка на живой сайт.
8. **В помощь руководителю** — методические материалы, нормативные документы модели, актуальная нормативная база (2025–2026) с ссылками на первоисточники.
9. **Личный кабинет** — анкета, диагностика (лист самооценки + комплексный тест 20 заданий), моя траектория (ИПР с конструктором), портфолио с загрузкой документов, прогресс во времени (история, график, сравнение «было → стало»).

## 🕹 Диагностика и ИПР

* Лист самооценки по 5 направлениям (шкала 0–4) и комплексный тест из 20 заданий с нормативными обоснованиями; варианты ответов детерминированно перемешиваются.
* Результаты сохраняются в БД: история замеров (дата, результат, уровень дефицитов), график динамики и блок «было → стало» с разницей в процентных пунктах.
* По дефицитам автогенерируются пункты ИПР; конструктор ИПР позволяет добавлять пункты вручную (направление, модуль, формат, целевой результат, срок, наставник), менять статус и удалять.

## 💻 Локальный запуск

Требования: Node.js **22.5+** (встроенный модуль `node:sqlite`).

```bash
npm install
npm start          # http://localhost:3000
npm run dev        # режим разработки с автоперезапуском
```

Пароли хранятся в виде хешей scrypt (демо-БД мигрирует автоматически), сессии — по одноразовым токенам, ответы в «Эффективном диалоге» публикуют только роли `expert`/`admin`.

## ✅ Тесты

```bash
npm test
```

Три уровня по принципам влога Claude Code о верификации («verification means running the change»):

| Уровень | Файл | Что проверяет |
|---|---|---|
| **E2E** | `test/e2e.test.mjs` | Настоящий сервер + временная SQLite (`KUZBASS_DB_PATH`, `KUZBASS_UPLOADS_DIR` изолируют окружение): статика и SPA-фолбэк, вход/выход/токены, анкета, диагностика с автогенерацией ИПР, конструктор ИПР (регрессия FK-бага), права доступа к чужим данным, портфолио с файлами на диске и защитой `/uploads`, права эксперта в диалоге, лимиты полей, голосование, защита от перебора пароля (429) |
| **Property** | `test/property.test.mjs` | Инварианты: процент самооценки всегда 0–100 на тысячах случайных входов, монотонность шкалы, границы 81/70/50, перемешивание вариантов — перестановка с раундтрипом `oShown[cShown] === o[c]` и детерминизмом |
| **Differential** | `test/differential.test.mjs` | Старая система (статичный `prototype.html`) против новой (`public/js/logic.js`) на одних входах: расхождение классификации дефицитов = баг |

Чистая логика вынесена в `public/js/logic.js` (подключается и в браузере, и в тестах через `module.exports`). Продакшен-данные тесты не трогают: сервер в тестах запускается с env-переменными во временном каталоге.

## 🚀 Развертывание на сервере

**Docker:**
```bash
docker-compose up -d --build
docker-compose logs -f
```
БД (`./data/kuzbass_edu.db`) и загруженные файлы (`./uploads`) монтируются через volumes.

**PM2 + Nginx:**
```bash
npm install -g pm2
pm2 start server/index.js --name "kuzbass-navigator"
pm2 save && pm2 startup
```
Пример конфигурации Nginx с `client_max_body_size 30M` и проксированием на `127.0.0.1:3000` — см. историю репозитория / типовую схему для Node-приложений.
